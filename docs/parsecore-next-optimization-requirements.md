# ParseCore 后续优化要求

> 记录企业文档管理项目嵌入 ParseCore 后，仍需要在 ParseCore 服务侧继续推进的优化项。本文只约束 `D:\个人文件\个人开发\解析管理中台` 仓库内的能力建设；宿主系统侧优化另见企业文档管理项目文档。

## 目标边界

- 保持 ParseCore 作为独立解析服务的稳定 API、配置、队列、解析质量与可观测能力。
- 优先处理会影响宿主系统可靠性、吞吐、诊断闭环的服务端问题。
- 不把宿主系统 UI、业务权限、文档库交互逻辑放入 ParseCore 仓库实现。

## 优先级一：队列可靠性与任务生命周期

1. 为解析任务补齐硬超时、取消、失败重试与幂等处理语义。
2. 明确队列表行的领取、续租、释放、失败落库规则，避免多 worker 重复消费或任务长期悬挂。
3. 对异步解析任务输出稳定的状态机：`queued`、`running`、`succeeded`、`failed`、`cancelled`、`expired`。
4. 增加队列压力下的回归用例，覆盖并发领取、worker 中断、超时回收、重复提交。

验收要求：

- 相同任务在异常重试后不会生成互相冲突的解析结果。
- worker 崩溃或进程重启后，遗留任务可被安全接管或明确失败。
- 队列测试能稳定复现任务生命周期边界。

## 优先级二：分阶段上传与大文件解析链路

1. 完善 `/v1/parse/uploads` 等分阶段上传接口的清理策略、保留期、容量限制与审计事件。
2. 明确本地临时文件、对象存储、桥接 API key、上传完成确认之间的安全约束。
3. 为大文件解析提供避免 base64 传输的推荐路径，并补齐配置示例。
4. 对超大 PDF、Office、Excel 文件建立冒烟用例，确认内存峰值与失败提示可控。

验收要求：

- 过期上传会被清理，未完成上传不会污染正式解析目录。
- 上传配额、文件大小、MIME 校验失败时返回稳定错误结构。
- 宿主系统可直接按文档完成大文件上传与解析任务提交。

## 优先级三：解析配置与 profile 治理

1. 将常见部署形态沉淀为 profile 或配置模板，例如本地解析、远程 OCR、队列桥接、pgvector、fake embedding。
2. 对配置字段做强校验，启动时输出可读错误，避免运行中才暴露缺项。
3. 在示例配置中标注必填项、默认值、敏感字段和生产环境建议。
4. 为 profile 加入单元测试，确保模板与配置解析器同步演进。

验收要求：

- 新部署可以从 profile 或示例配置快速启动。
- 配置解析失败时能定位到具体字段。
- 文档、示例配置、测试三者保持一致。

## 优先级四：OCR 与解析质量追踪

1. 记录 OCR 触发原因、回退路径、页级置信度、跳过页、失败页、最终采用的文本来源。
2. 增加坏页、空页、扫描 PDF、混合文本 PDF、图片型 Office 的基准样例。
3. 为 OCR fallback 设置可配置阈值，避免低质量结果静默覆盖原始解析结果。
4. 输出适合宿主系统展示的质量摘要字段。

验收要求：

- 每个解析结果都能解释“为什么走 OCR / 为什么没有走 OCR”。
- 质量下降时测试能捕获差异。
- 宿主系统无需解析内部日志即可展示质量与回退信息。

## 优先级五：性能、内存与稳定性基线

1. 建立 PDF、Word、Excel、图片、压缩包等核心格式的解析耗时与内存基线。
2. 对大文件解析增加流式或分批策略，限制峰值内存。
3. 对异常文件、损坏文件、密码文件输出稳定错误码。
4. 对外部依赖调用增加超时、重试、熔断与清晰日志。

验收要求：

- 性能基线可在 CI 或本地命令中复跑。
- 大文件失败不会拖垮服务进程。
- 错误结构能被宿主系统自动归类。

## 优先级六：可观测性与诊断闭环

1. 统一解析任务、上传任务、OCR 调用、向量写入的指标命名。
2. 补齐 Prometheus 指标、结构化日志、trace id、request id 与任务 id 的关联。
3. 输出宿主系统可消费的解析阶段耗时、重试次数、错误类别、质量评分。
4. 提供最小仪表盘或指标说明，降低生产排障成本。

验收要求：

- 一次解析请求可从 API、队列、worker、OCR、存储链路串起来。
- 指标名称和标签稳定，适合长期看板。
- 失败任务可以通过任务 id 快速定位主要原因。

## 优先级七：安全与发布门禁

1. 加强文件路径沙箱、临时目录隔离、上传文件名净化。
2. 远程 OCR、桥接服务、对象存储等外部地址需做配置约束，避免误连非预期端点。
3. API key 与敏感配置只允许通过安全渠道注入，日志不得输出明文。
4. 发布前至少覆盖单元测试、API 冒烟、配置模板校验、关键解析样例。

建议命令：

```powershell
py -3.13 -m pytest tests/test_asgi.py tests/test_config_parser_options.py -q
py -3.13 -m pytest tests/test_profiles.py tests/test_api_payloads.py -q
```

涉及 OCR、质量基准或性能基线的改动，应额外运行对应专项测试或 benchmark。

## 与企业文档管理项目的协作约定

- ParseCore 提供稳定 API、错误结构、状态机、质量摘要与指标。
- 企业文档管理项目负责业务侧队列编排、用户权限、文档库状态展示、前端诊断视图。
- 跨仓库变更先在本文记录 ParseCore 侧要求，再在宿主项目优化文档中记录接入计划。
