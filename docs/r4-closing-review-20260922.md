## 8. 2026-09-22 复评与按需修复

复评基线为 `2f93086`（与方案原基线 `b18a525` 对照），以下为本轮工作区修复。复评按用户要求检查实际开发，不将未实现的远期增强自动转为本轮需求。

| 已复现问题 | 本次修复 |
| --- | --- |
| 读取 Blocks 后恰逢发布切换，会返回 OLD 正文、NEW chunks 与版本标识；records 快路径也会用最新 job 标注旧正式记录 | 正式读取改从一个 SQLite 读事务取得已发布 run 的封存产物；records 使用相同快照并保留数据库分页。执行时将索引描述随产物封存，避免读取实时索引的另一个版本 |
| 同一 block 重跑覆盖旧图片文件；全租户清理只保护 default 租户；删除旧 run 的图片时不检查其他 run 的引用 | 图片路径包含内容摘要并原子写入；按 tenant/doc 保护正式与预览 run，在发布事务锁内复核清理资格，保留在跑任务和共享素材；移除重复逐 run 扫描素材的旧辅助路径 |
| 复核入口只核对 doc_id，不核对租户；人工复核还可绕过 rag profile 的索引隔离前提 | 核对 run 的租户归属；人工确认只处理质量结论，不能取消必需的后端能力条件 |
| Word 行内格式切换时逐 run 去空格，`Part number` 会变成 `Partnumber` | 保留格式片段之间的空格，从原生片段组成文本 |
| Excel 元数据预览被当作完整表格重写知识单元，后续分块丢失未预览行；知识单元摘要遗漏外置的合并声明 | 截断元数据不替换完整正文；摘要复用共享合并处理逻辑 |
| OCR 页面缓存未计入本地识别配置，配置变化仍读旧结果；损坏缓存的结构/编码可能抛异常 | 将影响 OCR 文本的本地选项纳入缓存身份；损坏条目作为未命中处理，不中断解析 |
| OCR 按文本去重误删不同位置的相同文字；增强页重排序将双栏交错，原生段落误标为 OCR；180° 表头没有进入旋转重读 | 按文本与位置共同去重，复用区域阅读顺序并按实际行来源标注；补齐 180° 文本矩阵识别 |

这些修复沿用现有产物、网格、OCR 与发布机制，没有新增解析引擎、费用管理或平台。保留原交付报告中已注明的真实中文双栏样本、视觉模型接入、Postgres/pgvector 部署等未验证项。

另外记录一个未扩范围的局限：表头括号中的普通词（如 `Status (Open)`）仍可能被单位启发式误判；后续结合实际字段样本处理，不在本轮另建单位词典。
